# Working in this repo

For people and coding agents. `main` is the live site: whatever merges there
deploys to players. GitHub enforces the rules below on `main`, for every account.

## Making a change

1. Branch from an up-to-date `main`. One branch for one change, named for it
   (`spell-search-ranking`). Never work on `main`.
2. Make the change. Edit the sources in `src/`, not the generated blocks in
   `tools/` and `site/` (they sit between "generated by scripts/build-tools.mjs"
   markers).
3. Run these, and commit what the build writes:

       node scripts/build-tools.mjs
       node --test

4. Open a pull request into `main`: what changed, why, and how you checked it.
5. The repo's owner reviews and merges. Don't merge your own, and don't try to
   get around a rule that blocks you: say what's blocked in the pull request.

## Conflicts

The tool pages and `data/spell-catalog.js` contain generated code, so parallel
branches often conflict there. Don't merge those blocks by hand: bring in
`main`, resolve the source files in `src/`, and run the build again.

## The database

Files in `supabase/migrations/` change the live database, and only the owner
runs them (`supabase db push`). So a migration needs its own note in the pull
request, and:

- Add a new file; never edit one that's been deployed.
- Keep the live site working before and after it runs: add before you remove.
- Never put a secret in the repo. The Supabase publishable key in `src/cloud.js`
  is public by design; the secret key and database password never belong here.

## Character data

`test/fixtures/characters/` holds snapshots of real characters for the tests.
They aren't the live saves, which are in Supabase, and they don't hold players'
names. Don't guess a character's facts, and don't copy book or wiki text into
the repo (the spell catalog holds short stat blocks and links).

## Design

`docs/design-system.md` has the rules for components, colour and spacing. Read
it before changing anything visible, and show the owner a prototype for anything
bigger than a small fix (`prototypes/`, written by `scripts/prototype-*.mjs`).
